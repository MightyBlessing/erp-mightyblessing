# 마이티블레싱 업무관리시스템

마이티블레싱 내부 결재·정산 시스템. 단일 HTML 페이지 하나로 돌아간다.

**운영 링크** — https://erp-mightyblessing-i7xj.vercel.app
저장소는 Supabase. 로그인은 회사 Google 계정, 또는 메일 링크.
어느 쪽이든 `@mightyblessing.com` 주소만 들어온다 (`allowed_emails` 에 넣은 외부 주소는 예외).

Google 로그인을 켜려면 Google Cloud Console 에서 OAuth 클라이언트를 만들고
승인된 리디렉션 URI 에 `https://<프로젝트>.supabase.co/auth/v1/callback` 을 넣은 뒤,
Supabase → Authentication → Providers → Google 에 클라이언트 ID·보안 비밀을 넣는다.
Workspace 라면 동의 화면을 '내부'로 두면 심사가 필요 없고 회사 계정만 쓸 수 있다.

메일 링크는 통수 제한이 있다. Supabase 기본 발송기는 시간당 몇 통이라
사람이 여럿이면 금방 막힌다. 커스텀 SMTP 를 붙여야 메일 본문도 고칠 수 있고
(6자리 숫자 `{{ .Token }}` 를 넣으려면 필요하다) 통수도 풀린다.

## 구성

| 파일 | 용도 |
|---|---|
| `erp.html` | 원본. 여기만 고친다 |
| `index.html` | 배포본. `erp.html`을 doctype·charset으로 감싼 것. Vercel이 이걸 띄운다 |
| `build.sh` | `erp.html` → `index.html` 생성 |
| `config.js` | Supabase 주소와 publishable 키. 공개돼도 되는 값만 넣는다 |
| `supabase/schema.sql` | 테이블·RLS·실시간. 최초 1회 |
| `supabase/domain-guard.sql` | 도메인 제한 |
| `supabase/profiles-guard.sql` | 남의 프로필 사진을 못 바꾸게 |
| `supabase/storage.sql` | 증빙 보관함(`evidence` 버킷) |

SQL 파일은 Supabase 대시보드 → SQL Editor 에 **내용을 붙여넣어** 실행한다.
파일 경로를 붙여넣으면 `syntax error at or near "~/"` 가 난다.

`erp.html`을 고친 뒤 반드시 `sh build.sh`를 돌려 `index.html`을 다시 만든다. 안 하면 Vercel 쪽만 옛 버전이 남고, **charset이 빠져 한글이 깨진다.**

## 저장소 세 갈래

화면은 하나인데 뒤가 셋이다. `db.collection(n).doc(id)` 라는 같은 모양 뒤에 숨겨 둔다.

| | 언제 | 데이터 |
|---|---|---|
| Supabase | `config.js`가 채워져 있을 때 (= 운영) | `docs` 테이블 한 장, 실시간 동기화 |
| Claude Artifact | `window.claude`가 있을 때 | 아티팩트의 `db` |
| 데모 | 둘 다 아닐 때 | localStorage. 하단에 주황색 띠가 뜬다 |

**데모 모드 예시 데이터에 실제 회사 데이터를 넣지 않는다.**

권한은 `members.role` 로 정한다 — `member` / `accounting` / `ceo` / `admin`.
`admin` 만 역할 지정과 로고·직인 교체를 할 수 있다 (RLS가 `config` 컬렉션을 막는다).

## 모듈

| 메뉴 | 내용 |
|---|---|
| 대시보드 | 결재 대기, 진행 중 문서, 월별 사례비 지급 |
| 전자결재 | 공문(4서식·대내외) / 지출결의서. 결재선·승인·반려, 승인 시 직인 찍힌 PDF |
| 회계 | 승인된 지출의 지급 처리, 행사·계정과목·지급수단별 집계, 증빙 유무 |
| 정산 | 행사별 사례비 계산 + 결재 |
| 역할 | 회계·대표 지정, 로고·직인·프로필 사진 (admin) |

## 데이터

| 컬렉션 | 내용 | 쓰기 권한 |
|---|---|---|
| `events` | 행사 정산 | interact |
| `approvals` | 정산 결재 기록 | interact |
| `docs` | 전자결재 문서 | interact |
| `people` | 지급 대상자 명부 (이름·연락처·세무 구분·계좌) | interact |
| `notifs` | 알림 한 줄씩 (`to`는 uid 배열 또는 전원을 뜻하는 `'*'`) | interact |
| `profiles` | 프로필 사진, 알림 읽은 시각 | **본인 행만** |
| `config/roles` `config/logo` `config/seal` | 역할·로고·직인 | admin |

증빙 파일은 `docs` 안에 넣지 않는다. Storage의 `evidence` 버킷에 올리고,
문서에는 경로와 200px 미리보기만 남긴다. 사진을 JSON에 넣으면
문서함을 열 때마다 전부 따라 내려와 느려진다.

알림 읽음 표시는 사람마다 `profiles/<uid>.notifReadAt` 한 칸뿐이다.
알림마다 사람 수만큼 읽음 행을 만들면 금방 불어난다.

`profiles` 를 저장할 때는 반드시 `saveProfile()` 을 쓴다. `set` 은 통째로 덮어쓰므로
직접 쓰면 프로필 사진이나 읽은 시각이 날아간다.

## 사람이 둘로 나뉘어 있다

`members` 는 **로그인하는 구성원**이다. 회사 계정으로 들어와 문서를 쓰고 결재한다.
`people` 은 **지급 대상자 명부**다. 외부 스태프는 로그인하지 않는다.
둘은 겹칠 수 있지만 같은 것이 아니다. 섞으면 둘 다 망가진다.

정산표의 사람은 `members[].pid` 로 `people` 을 가리킨다.
`n`(이름)은 과거 데이터 호환을 위해 남겨 둔다. `pid` 가 없으면 이름칸에 주황 테두리가 뜬다.

같은 사람에게 여러 번 지급한 것을 합쳐서 지급명세서 한 건으로 신고하려면
`pid` 가 있어야 한다. 이름 글자로는 띄어쓰기 하나만 달라도 다른 사람이 된다.

주민등록번호는 받지 않는다. 지급명세서에 필요하지만 법상 암호화해서 보관해야 하고,
넣을지부터 정하지 않았다. 세무 구분(국세청 분류)은 지금 자유 입력이다.

## 사례비 계산 규칙

```
행사 수입 − 운영비 − 세금 = 행사 잔여액
    × 50% = 사례비 예산
        ├─ 당일 일급   150,000 × 당일 근무 인원
        └─ 준비 사례비 = 나머지
              → 포인트 배분 (핵심 사전준비 11 / 제작 기여 7 / 단일 업무 3 / 초기 조사 0)
              → 만원 단위 내림, 1인 상한 300,000
              → 잔액은 운영통장 이월
```

**사례비는 당일 일급과 준비 사례비를 모두 포함한다.** 당일 일급은 운영비가 아니라 사례비 예산 안에서 나간다.

지난 실제 정산 건을 원 단위까지 재현하는 것을 기준으로 삼았다. 만원 단위 내림이 핵심이다 —
포인트 비례 배분을 만원 단위로 내리고 남는 금액이 그대로 이월 잔액이 된다.

행사별로 당일 일급을 운영비에서 따로 지급해야 하는 경우에만 `wageSrc: 'opex'`로 바꾼다 (화면에서는 `당일 일급 재원 → 운영비 별도`).

> 이 저장소는 공개다. 실제 행사명·금액·개인 연락처는 코드에도 문서에도 넣지 않는다.
> 운영 데이터는 전부 Artifact의 `db`에 있고 저장소에는 없다.

## 공문 양식

2026-11-14 충현교회 장소 대관 공문을 기준으로 한다.

- 머리말: 기관명 + 주황 가로줄, `수 신 / 참 조 / 제 목`
- 본문: 번호 문단
- 개요 표: 가. 행사명 / 나. 행사목적 / 다. 일시 / 라. 주관 / 마. 주최·협력 / 바. 세부장소 / 사. 참석인원 / 자. 기타(요청)사항
- 맺음: `끝.` → 발신명의 + 직인 → 시행 블록 (문서번호, 주소, 전화, 메일)

## 주의

Artifact의 `db`가 내려주는 문서 본문은 **동결(frozen)되어 있다.** 그대로 수정하면 `object is not extensible` 오류로 조작 전체가 실패한다. 반드시 복사본을 만들어 쓴다.

로컬 파일로 열면 `window.claude`가 없어 이 동결 동작이 재현되지 않는다. 게시 후 실제 링크에서 눌러보고 확인한다.

## PDF

브라우저 인쇄창을 거치면 날짜·쪽번호·웹주소가 종이에 같이 찍힌다.
CSS로는 못 막고 사람마다 설정이 다르다. 그래서 html2canvas + jsPDF로
화면을 직접 찍어 A4 파일로 만든다. `인쇄` 버튼은 종이로 뽑을 때만 쓴다.
